OAuth2 Client Credentials:: If you select ‘OAuth2 Client Credentials’, the server requests an access token directly from the token endpoint by using the client ID and client secret, and sends that token with each request. No browser sign-in is required, so this method also works when the server is behind a firewall or VPN. Follow the steps below:

.. Enter the ‘Client ID’ and ‘Client Secret’.

.. Enter the ‘Token URI’, which is the address of the token endpoint of the authorization server.

.. *_Optional:_* Enter the ‘Scope’ if the API requires one.

.. *_Optional:_* Enter the ‘Audience’ if the authorization server requires it to identify the API that the token is for.

.. In the ‘Client Authentication’ menu, choose how the client ID and secret are sent to the token endpoint: ‘HTTP Basic Header’ (the default) or ‘Request Body’. Choose ‘Request Body’ if the token endpoint does not accept credentials in an HTTP Basic header.
+
NOTE: The access token is kept in server memory and is not saved with the data source. The server renews the token shortly before it expires. If the API rejects a token (HTTP 401), the server requests a new token and retries the request once.
