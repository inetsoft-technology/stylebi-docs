[[Troubleshooting]]
== Troubleshooting

Salesforce connections authenticate using the SOAP `login()` API, and the errors it returns are not always self-explanatory. This section covers the errors most commonly seen when setting up a Salesforce connection.

=== Invalid username, password, security token; or user locked out

This generic Salesforce error can mean several different things:
[square]

* The username or password is incorrect.
* The password and security token are individually correct but do not match each other. Make sure both  password and  token are current, and reenter the concatenated string into the ‘Password’ field.
* A Login IP Range restriction on the user`'s Salesforce profile is blocking requests from the StyleBI server's IP address.

To determine which of these applies, log into Salesforce and go to menu:Setup[Quick Find > Login History]. Find the failed attempt (it should match the timestamp and source IP of the connection attempt), and check its ‘Status’ column, which may report a more specific reason (for example, "`Invalid Password`") than the generic message StyleBI displays.

=== SOAP API login() is disabled by default in this org

Salesforce disables the legacy SOAP `login()` operation by default for any org created in the Summer `'23 release or later. This affects most new Developer Edition, scratch, and trial orgs. No password or security token will work until a Salesforce administrator re-enables it. Follow the steps below:

. In Salesforce, go to menu:Setup[Quick Find > User Interface].
. Check the ‘Enable SOAP API login()’ checkbox.
. Press btn:[Save].
+
NOTE: Salesforce has announced that the SOAP `login()` operation will be fully retired in the Summer '27 release. Enabling this setting is a temporary workaround, not a permanent fix.

=== SOAP API login() requires the use any api auth user permission

This means an administrator enabled the narrower ‘Enable SOAP API login() to Users with the Use Any API Auth user permission’ checkbox instead of the plain ‘Enable SOAP API login()’ checkbox. There are two ways to resolve it:
[square]
* Go back to menu:Setup[Quick Find > User Interface] and check the plain ‘Enable SOAP API login()’ checkbox instead. This removes the permission requirement entirely.
* Grant the connecting user the ‘Use Any API Auth’ system permission through a Permission Set.  Follow the steps below:

. In Salesforce, go to menu:Setup[Quick Find > Permission Sets], and press btn:[New]. Give the permission set a name, and press btn:[Save].
. Open the new permission set, and select ‘System Permissions’.
. Press btn:[Edit], check ‘Use Any API Auth’, and press btn:[Save].
. Back on the permission set page, select ‘Manage Assignments’.
. Press btn:[Add Assignment], select the connecting user, and press btn:[Next] and btn:[Assign].
