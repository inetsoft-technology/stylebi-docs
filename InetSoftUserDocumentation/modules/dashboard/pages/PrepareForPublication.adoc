Summary: How to prepare a Dashboard for publication across different devices and languages. Covers device-specific layouts and print layouts for paginated, report-style output since StyleBI has no separate "report" asset (CreateDeviceLayout), modular Dashboard design (ModularizeDashboard), and multi-language localization (LocalizeDashboard). The following sections explain how to arrange components on a Dashboard for publication across a variety of devices and languages. For information on making a Dashboard available to other users, see xref:PublishDashboard.adoc[].

[square]
** xref:dashboard:CreateDeviceLayout.adoc[]: Define or select a device class based on screen size, and specify how a Dashboard should be displayed for that device class. Also covers print layouts, which produce paginated, report-style PDF output -- StyleBI has no separate "report" asset, so this is how a Dashboard gets page breaks, page numbering, and repeating headers/footers.
** xref:dashboard:ModularizeDashboard.adoc[]: Build a complex Dashboard from several smaller Dashboards.  This allows you to compartmentalize functions and integrate data from multiple sources into a single presentation.  Modularization also facilitates team development and maintainability.
** xref:dashboard:LocalizeDashboard.adoc[]: Translate a Dashboard into one or more alternate languages.  The Dashboard is then displayed to the user in the appropriate language based on the user's locale setting.
